## Summary

目标是统一会话流中工具调用展开后的内部区块视觉，并将 HITL 交互移出会话流：工具输出、diff、bash 命令、thinking 全文、note 全文使用独立带背景的圆角卡片，对标图二深色代码块；首层工具调用展开时左侧增加竖向连线；thinking 折叠标题简化为 `Thought` 加时长，不再显示首段摘要；审批与提问改为输入框上方弹出层，类似 Cursor Agent 形态。

已确认决定：thinking 标题采用 `Thought 5s` / `已思考 5s`，时长按相邻 block 时间戳差推导，live 保持 `Thinking…` 呼吸态；首层指脱离 phase 轨道直接渲染的行，即 `phase-single` 与 `BlockView` 直出；背景范围覆盖工具与 thinking/note，审批与提问不做行内背景卡而是弹出层；本次仅改代码，记录 Figma 未同步范围。

范围限定在渲染器：会话流折叠与卡片样式、`tasks` 与 `panel` 相关文案、Composer 上方 HITL 弹出层及其与 transcript 行内等待态的衔接。默认复用语义 token：`--ata-surface-raised` 做卡片与弹出层底、`--ata-radius-control` 做圆角、`--activity-connector` 做连线，避免新增硬编码颜色。

非目标：不改主进程 transcript schema、IPC 与权限判定，不改队列、停止与继续逻辑，不做全量 Figma 重构，不新增持久化字段；thinking 时长跨重启精确计时另立方案。

验收以渲染检查为准：内部卡片背景与圆角一致，首层竖线连续且不与 phase 轨道重复，thinking 折叠态只读出时长标题，HITL 弹出层在输入框上方正确呼出、聚焦、键盘可用，行内保留等待占位与已决结果，中英文案一致。

## Risks

- thinking 时间戳多为同一消息级：相邻差值可能为零，需要下限钳制为 1s 并与 `TurnHeader` 的格式化保持一致。
- 首层竖线与 phase 轨道并存：`phase-single` 与直出分支需独立类名，避免在已有轨道外再加一条竖线。
- 背景统一影响密度与对比：`--ata-surface-raised` 在长输出与嵌套滚动下需要复查内边距与滚动容器圆角裁剪。
- HITL 移出改变现有测试与焦点：`approval.test` 与 `question.test` 的行内按钮断言需要迁移到弹出层，并补齐等待占位断言。
- 弹出层与 Composer 布局耦合：展开态、附件、队列同时存在时，弹出层不能遮挡输入或撑破 `overlay-footer`，窄宽与短高需要单独截图。
- 键盘冲突：Enter 发送、Esc 关闭与 Composer 快捷键共存，需要明确焦点上下文内的优先级，避免误触发送或关闭面板。
