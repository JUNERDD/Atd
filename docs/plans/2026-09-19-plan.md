# 合并模型选择器与模型配置触发器

Status: Completed - implemented T2–T10
Created: 2026-09-19
Approval: Implemented (user authorized via 执行)

## Summary

目标：把面板 Composer 底部目前的两个独立触发器（模型选择器 + 思考档位选择器，见图一红箭头）合并为图二所示的单一触发器。触发器文案聚合为 `模型名 + 上下文 + 档位`（例：`Muse Spark 1.3 1M Max`），点击后弹出同一菜单，内含 `Context / Effort / Model` 三行。HUD 单窗口约束下不用双浮层子菜单，改为单一 `Popover` 内钻取导航：根视图三行，点击 Effort/Model 在同一窗口内切换子视图并带回退，模型子视图保留完整 `Command` 搜索。同步合并命令编辑器固定模型区。

已确认的现状（仓库证据）：
- 双触发器的唯一所有者是 `ComposerConfiguration`：`ModelPicker(compact)` + `ThinkingLevelSelect(compact)` 并排于 `.composer-model-group`。
- `ModelPicker` = `Popover + Command` 可搜索跨连接模型列表；`ThinkingLevelSelect` = `Select`，选项来自主进程 `providers:levels`（`off/minimal/low/medium/high/xhigh/max`），少于 2 个选项时禁用。
- `RunPolicy` 目前只有 `model` + `thinkingLevel`，没有 `context` 可选字段；`ModelDefinition.contextWindow` 是模型固定能力，不是可选项。
- pi 上游（v0.85.1 只读）结论：`contextWindow` 是模型定义固定值，仅用于压缩阈值、溢出判断与页脚 `percent/1M` 展示；TUI 只有独立的模型选择器与思考档位选择器，无按次可配的 context 选择器。`ThinkingSelector` 标题为 `Thinking Level`，底层 provider 字段为 `reasoning_effort/thinking.effort`。因此 Context 行应为只读展示，不新增 `RunPolicy` 字段。
- Q2 已确认：全局改名为 `Effort`（含提供商设置与命令编辑器），仅改展示文案，底层 `thinkingLevel` 字段与 IPC 值保持不变以保兼容；中文译法待定（候选：推理强度）。
- `DropdownMenu` 已有 `Sub/SubTrigger/SubContent`（自带 `ChevronRight`），视觉上最接近图二；`Popover` 则是现有模型搜索的容器。

非目标：不改主进程 IPC 形状与权限判定，不改队列/停止/继续逻辑，不新增 `RunPolicy.context` 字段，不做全量 Figma 重构。

约束：保留模型搜索能力与不可用/无目录/空状态；保留思考档位少于 2 项时禁用与不可用档位回退语义；中英文案键集合一致；350 行文件上限；保留工作区现有脏改动。

实施结果：`ModelConfigPopover`（300 行）已落地并接入 Composer（紧凑）与命令编辑器（全宽）；`Effort/推理强度` 全局改名完成，中英键集一致；静态与单测全绿；冒烟因新鲜档案中文渲染导致英文断言失败（预期内），快照证实中文空态触发器与根视图正确。
